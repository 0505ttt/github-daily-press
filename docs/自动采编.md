# 自动采编说明

本地与 GitHub Actions 使用同一入口：`python -m gh_daily update`。日常推荐云端定时生成，再在本地应用中同步阅读；本地生成使用相同的采集与校验流程。模型设置、启动和同步方法见 README。

## 每次运行做什么

1. 先采集 AI 来源，只接收生成时点前 48 小时内、带可验证发布日期的条目。来源顺序为 GitHub、OpenAI、Anthropic、智谱、Kimi、X/Twitter、TechCrunch、Hugging Face 博客与论文、Google Research、中文科技媒体。
2. 把已经采集的资料交给配置的模型，用中文归纳并引用来源编号。模型不能自行提供新链接。没有模型、模型故障或没有可验证新内容时，该子任务明确失败；不生成看似完成的虚构日报。
3. 从 GitHub Trending 实时读取日榜 Top 10，补充仓库顶部描述与 README。项目数字只来自真实抓取；API 缺失和失败不改写为零。模型故障时仍保存真实榜单与仓库原描述，并将解释状态标为待重试。
4. 更新每个项目的档案与总索引。相同日期的日榜和周榜分别记录；同一周期重复运行不增加次数。
5. 周一读取真实周榜 Top 15，并从最近七天已有 AI 日报提取回顾。每月第一天只聚合上月本地日报与档案，不冒充 GitHub 官方月榜。
6. 重建阅读站点和杂志。AI、日榜、周榜、月榜各自记录成功或失败；一个失败不阻塞其它任务。

## 数据与时间口径

- 定时采用北京时间每天 08:30。GitHub Actions 对应 UTC 的 `30 0 * * *`，可能延迟，不能把定时配置当成准点成功的证据。
- 采集保留实际观测时间。不能指定过去日期再用今天的实时 Star 伪造历史；只有当日本机留存过真实快照，或已经存在有效报告，才可继续当期未完成工作。
- “Star 观测变化”使用当月最早与最晚可用观测之差，展示两个观测日期。缺失月初或月末时，不称为完整自然月增长。只剩一个总星观测时显示“暂未获取”。
- 每个来源地址最多尝试两次；AI 采集上限十分钟，整次更新预算二十分钟。正文响应限制为 4 MiB。资讯不足允许少报，不以旧消息凑数。
- 动态页面不一定提供可读取日期。官方页面不可读取或没有带日期的新内容时，使用 Bing 公开 RSS 做官方域名限定的搜索，再打开最多两篇原文验证发布日期。搜索摘要与摘要日期不能作为事实来源；X/Twitter 找不到可核验公开原文时如实记录，不扫描私人账号。

## 重试、重复运行与失败恢复

- 已有日报、周报、月报和 AI 日报本身是幂等依据，换机器或 Actions 丢失运行状态后也不会重复计数。
- AI 首次失败、GitHub 首次成功时，稍后重新运行只补 AI 与融合板块。报告中尚未完成的项目中文解释也会重试，不重新抓榜或增加档案次数。
- `.runtime/` 保存本机来源快照、子任务状态和进程锁，不上传仓库，不放入网页公开目录。公开文件用同目录临时文件原子替换；新版本失败时保留上一份有效内容。
- 构建成功后保存输入内容摘要。上次构建失败、输入发生变化，或换机器后缺少摘要时，下次即使所有报告已存在也会重新构建；只有输入与上次成功构建一致时才跳过。
- 正在运行时再次触发，返回“已有采编任务运行中”。本地服务与命令行共享同一个跨进程锁。
- 接口 `run_update(root, date_str=None, force=False)` 返回 `ok`、`status` 与 `tasks`。总体状态为 `success`、`partial` 或 `failed`；`ok=false` 可以同时有已完成子任务，排查时以各子任务状态为准。
- `force=True` 会重新采集当期数据并重写报告，更新同日期、同日周类型的观测值，仍不增加历史计数；日常重试不需要强制模式。

## 云端配置与检查

工作流只提交日报、AI 日报、项目档案、索引与构建产物。模型 URL、名称可以使用仓库 Variables，API Key 使用 Secrets。不要把个人配置目录、`.runtime/`、环境文件、执行日志或服务端错误原文提交到仓库。

首次部署先手动触发一次 Actions，检查每个子任务结果、来源条数和生成页面。工作流文件已经存在不代表云端已成功运行；页面中的时间也只表示真实成功生成或同步的时点。网络异常、无新内容和模型失败应按实际情况处理后再次触发。

## 测试

运行 `python -m unittest tests.test_pipeline -v`。测试使用固定网络与模型替身，覆盖日期筛选、空榜、最多两次请求、恶意 HTML、未授权引用、日周同日幂等、月度聚合、模型失败后补齐、独立子任务失败和并发锁；不会调用真实收费模型。
