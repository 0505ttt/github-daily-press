# AI 日报事实与引用核验

从 2026-10-26 起应用于新日报与融合速递；此前档案保留，不将本次修订称为全库核验。

## 编辑必须逐条确认

1. 打开具体原文，记录标题、发布机构、发布日期、事件发生日期和读取日期。首页、栏目、RSS、搜索摘要只用于发现线索，不能作为结论依据。原文打不开、付费墙只剩无关摘要、未标日期时，如实少报。
2. 明确标记官方公告/厂商自报、项目作者自述、第三方报道、分析观点或未证实信息。可靠媒体报道可以保留，但不能改写成已独立确认的官方财报或公告。
3. 发布日期和事件日期分开。近 48 小时报道旧事件时注明回顾；旧公告和无发布日期文档只能放背景，不能冒充今日新发布。
4. 每条结论对应同一原文的直接支持片段。检查模型全名、版本、基准名称、测试条件、单位、币种、时间跨度与指标方向。厂商评测不是独立复测；百分点不是百分比；净亏损不是现金支出；计划开放不是已经开放。
5. 降价比较必须有同模型、同计费项、同单位与币种的两个带日期价格依据；缓存、批处理、输入/输出和企业协议价格分开。只有现价表不能证明历史降幅。排名必须有对应日期、榜单版本和方法。
6. 原文不支持的数字和推断删去；不把传言、补偿政策、评论联想写成发布预告。改正原稿后同步融合段、相关周报和重新构建的杂志/网页。

## 程序已执行的检查

- `sources.collect_ai` 对 RSS/公告/搜索候选逐篇读取原文标题、正文和原文发布日期；清除导航、推荐位与侧栏；不采用 RSS/搜索日期代替文章日期。原文读取失败、无正文、无可信日期或超出 48 小时窗口时拒收。来源失败不阻塞其他来源。
- 官方域名搜索复用已经读取的原文；一次采编中同一文章地址只进行一次有界读取，底层最多请求两次，不重复下载失败地址。
- 模型仅可选择采集来源编号，另须提供 1—3 段来自该原文正文的连续证据。证据原文匹配失败、正文另造链接、英文模型/机构名称或数字不在证据中时拒绝该批 AI 成稿，保留已有内容待重试。证据留在本机运行数据中，不把长引文自动复制到公开日报。
- `build_site` 在生成、导入、发布和 Pages 构建时统一拦截新 AI 日报/融合段中的首页、RSS、栏目、搜索链接以及没有来源的标准新闻条目。与采编使用同一检查函数，手工 AI 工具也经过这道构建检查。

单独检查命令：

```bash
python -m gh_daily.citations --root . --since 2026-10-26
python -m unittest tests.test_citations tests.test_pipeline -v
```

入口检查不联网，也不证明页面可达或结论正确。程序不能证明中文语义蕴含、金额换算、单位、比较方向、所有模型别名及厂商测试公平性；“80% 营收增长”与“80% 降价”可共享数字，所以必须人工逐条确认。付费墙无法访问的内容不能以自动检查通过为由采用。该检查也不追溯认证历史文件或现有安装包。

## 使用已有 AI 工具

写稿前按上方清单联网核验；不要仅复制工具搜索结果。自动生成不足 8—10 条时，融合段按已核验数量展示，不凑数。正文注明资料不足，背景与当期新讯分开。构建报错时先修复引用，再发布；GitHub Pages 成功只表示构建部署完成，不是事实核验结论。
