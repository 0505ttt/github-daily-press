# 使用已有 AI 工具采编

你已经在用 ZCode、Claude Code、Hermes、Kimi Code 或其他 AI 工具时，可以让它读取项目、联网核实资料、按规范生成日报，再运行项目的构建和发布命令。模型由工具自己的授权提供，**不用再为本项目填写一份 API Key**；工具本身的订阅或调用费用仍按它的规则计算。

## 先确认工具能做什么

完成整条任务需要：联网查资料、读写指定资料目录、运行项目命令，以及你明确授权的 GitHub 发布权限。ChatGPT 等产品只在具体环境提供这些能力时才能参与全流程，普通聊天窗口不能凭空读写电脑上的项目。

本机工具设置定时任务后，需要电脑开机且工具正常运行。云端工具是否关机后继续运行，取决于任务实际所在环境及平台能力。**不能仅凭软件名称或“已设定时”判断它在云端执行。**

## 一次性准备

1. 下载公开版源码作为工具和说明书，或使用桌面应用。本地杂志与作者的公共网站分别保存。
2. 按[安装说明](安装与模型设置.md)安装 Python 依赖；已有桌面安装包不等于当前 AI 工具自动获得了源码命令环境。
3. 执行 `python -m gh_daily workspace` 查看本机工作区。首次是空白的，让 AI 在这里创建自己的日报和档案；不要复制作者历史作为自己的起点。
4. 只有需要公开发布时，再准备自己有权维护的独立公开仓库，执行 `gh auth login` 并确认 remote。不要将整个个人工作区设为公开目录，也不要把 token 或登录信息贴给模型。
5. 让工具先手动完成一次，检查日报和项目档案，再按该工具实际支持的方式设置北京时间每天 08:30 定时。

## 可复制的完整任务指令

将下面的目录替换为实际位置，再交给工具。**默认只维护自己的本地杂志**，无需 GitHub 上传；希望维护公开网页时，再明确选择“公开仓库维护”模式。

```text
你是「GitHub 每日项目推送」的中文编辑。请在指定目录完成今天的真实采编、档案更新和阅读页构建。

模式：〈默认填写“本地个人杂志”；确需公开上传时填写“公开仓库维护”〉
项目源码目录：〈填写源码目录，用于读取规范和运行命令〉
本机工作区：〈执行 python -m gh_daily workspace 后得到的目录〉
公开仓库目录：〈仅公开模式填写独立公开仓库目录〉
时区：Asia/Shanghai
发布：〈首次填“只生成与检查”；确认仓库和权限后可填“允许发布至本仓库”〉

一、开始前
1. 阅读源码目录内 AGENTS.md、README 和 docs/自动采编.md，不修改源码、密钥、原有调度或私人资料。
2. 本地模式只在“本机工作区”写日报和档案，不导入作者公共历史。首次空白是正常状态，第一份成功日报即第001期，后续保留累计资料。公开模式在指定公开仓库维护原有公共历史，不能为新读者重置它。
3. 以实际运行日期为准。按当天日期检查日报、AI 日报、周报和月报，已成功完成的内容跳过，不重复归档或累计。
4. 无法联网时停止相应采集，并报告原因。不能凭记忆编造项目、排名、星数、发布日期或来源链接。

二、先采集 AI 资讯
1. 查找最近 24—48 小时的官方公告、项目材料、RSS 和论文。优先来源为 GitHub、OpenAI、Anthropic、智谱、Kimi，再看 Hugging Face、Google Research 等可核实材料。
2. 每个来源最多尝试两次，总采集时间控制在十分钟内。只收能核实时间与原文的材料，不以搜索摘要代替原文，不拿旧消息凑数。
3. 写入 AI前沿资讯/日报/YYYY-MM-DD-AI日报.md。结构为：
   # AI前沿日报 YYYY-MM-DD
   ## 一、大模型动态
   ## 二、Agent与工程实践
   ## 三、GitHub热门AI项目
   ## 四、论文技术速览
   ## 五、产业与观点
   每条采用「**标题** — 两三句中文介绍。[来源](已核实原文链接)」。
   文末写一句话总结和今日采集情况，说明成功、失败和无新内容的来源。资料不足允许少报。

三、GitHub 日报与项目档案
1. 实时读取 https://github.com/trending?since=daily ，取实际可获取的 Top 10。
2. 排名、仓库 owner/repo、主语言、总星和当日新增必须来自真实抓取。读取仓库 README 或顶部描述再写用途；拿不到的数据写“暂未获取”，少于十个如实说明。
3. 对照源码内已有日报的结构，保留黑绿版式、五列榜单速览表和项目卡片结构；只参考格式，不把作者历史或旧数字复制进本机工作区。加入带原文链接的 AI 前沿速递。
4. 写入 GitHub项目分析/GitHub热点日报_YYYY-MM-DD.html。日期和期号分开：期号由杂志构建器按有效收录报告的时间顺序生成，不把日期的“10日”当成“第10期”，不虚构缺失日期。
5. 在 GitHub项目分析/项目分类库 全树查重。项目档案用 owner-repo.md；首次建档，已存在只更新对应字段与历史上榜记录。相同日期、相同榜单类型不得重复计数。
6. 保留主语言、首次上榜、最近上榜、分类、累计上榜与带日期的历史记录。更新 _索引.md，缺失值不当成零。

四、周报与月报
1. 周一读取 https://github.com/trending?since=weekly ，使用真实 Top 15，写入 GitHub热点周报_YYYY-Www.html。采用 ISO 周号，档案中以 W#排名 区分周榜。
2. 每月第一天聚合上个月已有日报和档案，写入 GitHub热点月报_YYYY-MM.html。不得抓今天的榜单冒充上月数据。
3. 月报区分上榜次数、当月新增项目和 Star 观测变化；星数变化使用最早和最晚可用观测，注明日期，不足以代表完整自然月时说清楚。

五、构建、检查与发布
1. 使用已安装依赖的 Python。在本地模式执行：
   python -m gh_daily --root "〈本机工作区〉" build
   python -m gh_daily --root "〈本机工作区〉" privacy
   公开模式则在公开仓库目录执行：
   python -m gh_daily --root . build
   python -m gh_daily --root . privacy
2. 确认页面、内嵌数据、档案和附件没有私人路径、凭据或执行日志。若 AI 先输出到单独资料目录，用 --root 明确导入目标，不能把本地私人杂志误发布到公共仓库。
3. 检查今天的报告真实存在且可解析，日周月周期正确，重复执行没有新增重复历史。新内容失败时保留上一份有效内容。
4. 本地模式不运行 publish。只有选择公开模式且任务开头明确“允许发布至本仓库”时，才在该仓库执行 python -m gh_daily --root . publish。它只发布限定的公开产物；不得自行 git add 整个个人目录，也不得上传配置、缓存、原始请求或执行日志。
5. 分别汇报“采编完成、检查通过、已提交、已推送、网页已部署”的真实状态。推送后还需确认 Pages 部署结果，不能把本地文件已保存说成网页已更新。

六、最终汇报
全中文列出日期、各子任务状态、产出文件、项目及资讯数量、档案新增/更新、来源缺失、构建与发布结果；失败任务单独说明，不影响其他任务的真实状态。不要在汇报中输出密钥。
```

工具不能运行命令时，可以先生成资料，交由具有本地执行能力的工具完成导入与发布。它不能设置定时时，也不要把“记住每天做”当成已创建了定时任务。

## 从 AI 输出目录导入自己的本地杂志

如果工具先把资料写在单独目录，执行下面命令。导入目标是 `workspace` 显示的本机工作区，这一步不需要 Git，也不上传：

```bash
python -m gh_daily workspace
python -m gh_daily --root "本机工作区" import-content --source "AI输出目录"
python -m gh_daily --root "本机工作区" build
```

正常关闭和重启不会重置本机工作区。同步仓库默认留空，除非你主动选择来源，否则不拉取作者内容。

## 维护公开仓库时，再导入与发布

如果现有自动任务在另一个目录生成日报，公开版不会因为文件同名而自行跟着更新。需要明确的导入和发布步骤：

```bash
python -m gh_daily --root . import-content --source "资料目录"
python -m gh_daily --root . privacy
python -m gh_daily --root . publish
```

这些命令在独立公开仓库目录执行，`--root .` 必须放在子命令前，表示明确操作当前公共仓库。资料目录与公开目录分开后，原始资料可以继续保留；只让符合白名单与隐私规则的阅读资料进入公开版。发布命令不负责凭空生成当天榜单，也不替代 AI 工具的调度。

当 GitHub 收到公开内容后，Pages 工作流继续部署在线网页。每一步都应确认结果；查看已发布网页不需要你的电脑一直开机，但下一次本地采编仍需要本机运行。
