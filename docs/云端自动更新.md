# 云端自动更新：电脑关闭后，谁在运行？

## 先分清采编、保存与阅读

**采编任务要有电脑运行，网页阅读不需要每个读者再运行采编。** 这里的“电脑”既可以是自己的电脑，也可以是 GitHub 提供的临时云端电脑。

| 环节 | 谁负责 | 自己的电脑关闭后 |
| --- | --- | --- |
| 本地采编、Ollama 或本地 AI 工具 | 自己的电脑 | 无法继续执行本机任务 |
| GitHub Actions 采编 | GitHub 托管的临时运行器 | 仍可按计划执行；需正确配置且运行成功 |
| 保存公开日报和档案 | 自己的 GitHub 仓库 | 已提交的文件继续保留 |
| 提供在线阅读网页 | GitHub Pages | 已部署网页继续对读者开放 |

**API Key 是调用模型的凭据，GitHub Actions 才是运行程序的地方。** 在本地填写云端模型 Key，并不会把整个项目自动搬到云端。

## 只想阅读作者的杂志

直接打开[在线杂志](https://0505ttt.github.io/github-daily-press/)，无需自行部署、配置 Secrets 或填写 Key。作者完成采编、检查和发布后，读者看到新版本。每日更新是发布节奏，不是页面持续实时抓取榜单的承诺。

## 用自己的仓库做云端采编

云端流程是：到点启动 GitHub 临时电脑 → 安装依赖 → 抓取真实来源 → 调用模型归纳 → 检查 → 将公开结果保存回自己的仓库。运行器结束后临时环境会消失，已经提交的日报、档案和网页仍然留在仓库。

1. Fork 本仓库，或把公开版作为仓库根目录上传，默认分支使用 `main`。不要把个人工作区整包上传。
2. 在 **Settings → Secrets and variables → Actions** 添加以下项目：

| 类型 | 名称 | 填写内容 |
| --- | --- | --- |
| Secret | `LLM_API_KEY` | 自己的模型密钥 |
| Variable | `LLM_BASE_URL` | 兼容接口根地址，包含服务商要求的 `/v1` |
| Variable | `LLM_MODEL` | 模型实际名称 |
| Variable | `ENABLE_DAILY` | 填 `true`，启用每日采编 |

3. 在 Fork 的 **Actions** 页面按 GitHub 提示启用工作流。
4. 打开 **每日情报采编 → Run workflow**，先手动跑一次。
5. 查看各子任务、来源情况和提交记录。只有运行成功且文件真正保存，才说明自己的云端采编已接通。
6. 要发布自己的在线网页，在 **Settings → Pages → Build and deployment** 选择 **GitHub Actions**，运行仓库的阅读站点部署工作流。自己的地址通常为 `https://你的用户名.github.io/仓库名/`，以 Pages 显示的实际网址为准。

定时计划为 UTC 00:30，即北京时间每天 08:30；周一增加周报，每月第一天聚合上月数据。GitHub 调度可能延迟或漏跑，长期无活动的仓库可能被暂停定时，需要重新启用。手动运行会继续当天未完成部分，不拿今天的数据伪造过去的日报。

仓库保护规则若禁止工作流提交，需要按自己的协作规则处理。不要为绕过错误关闭全部保护。

## 用已有 AI 工具采编，再发布网页

也可以让 ZCode 等已有工具在采编目录生成资料，再导入独立公开版，检查后发布。无需在项目中另配模型 Key。可复制指令见 [AI 工具采编](AI工具采编.md)。

```bash
python -m gh_daily --root . import-content --source "资料目录"
python -m gh_daily --root . publish
```

命令在独立公开仓库目录执行，`--root .` 放在子命令前，明确维护当前公共仓库。使用已经安装项目依赖的 Python，发布前需 `gh auth login` 并确认 Git remote 指向自己有权维护的仓库。导入仅处理公开内容，发布只提交限定的公开产物；密钥、执行日志和私人配置不在其中。本地个人工作区不需要上传。

**本地 AI 工具的定时仍需要本机运行。** 在线网页在关机后仍可阅读，与“本机在关机后还能生成当日内容”是两回事。云端 AI 工具能否按时采编，还取决于具体环境是否具备联网、目标仓库读写和调度权限。

## 本地独立工作区与可选同步

日报存于 `GitHub项目分析`，AI 日报存于 `AI前沿资讯/日报`，构建后的阅读页面在 `dist`，版本清单为 `content-manifest.json`。

本地首次部署从空白开始，资料在用户数据目录，第一次成功生成自己的日报为第 001 期，后续持久累计。它不带作者的公共历史，也不默认选择或同步公共仓库。公共网站继续保留完整历史，两者分别管理。

需要同步自己的其它设备或主动阅读某个信任仓库时，才在本地设置中填写自己拥有或明确信任的公开仓库 `owner/repository`，点击“立即同步”。选择仓库后，服务启动时及运行期间会检查更新。同步只更新阅读数据，不覆盖本地代码或模型配置；本地 PWA 需服务运行才能同步，离线时继续读上次缓存。

## 费用与失败处理

公开仓库使用标准 GitHub 托管运行器时，费用按 [GitHub 当前政策](https://docs.github.com/en/billing/concepts/product-billing/github-actions)执行；模型调用由所选服务商收费。超时、输出与重试上限不等于账单硬限额，请在服务商控制台设置预算。GitHub 云端不能直接访问个人电脑里的 Ollama 回环地址。

模型、来源或榜单失败会分别记录，已有有效内容保留。部分成功的报告可以先保存，工作流仍会标出未完成任务；重新运行不会重复计数。发现白名单外改动、私人路径或疑似凭据时停止发布，错误信息脱敏。

官方说明：[Secrets](https://docs.github.com/en/actions/concepts/security/secrets)、[定时规则](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)、[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)。
