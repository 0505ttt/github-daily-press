# 云端自动更新

## 文件保存在哪里

流程为：GitHub 云端临时电脑运行采编 → 检查结果 → 将公开报告提交到自己的仓库。历史日报放在 `GitHub项目分析`，AI 日报放在 `AI前沿资讯/日报`，可同步页面在 `dist`，内容版本清单为 `content-manifest.json`。

密钥、原始请求和本机配置不提交。云端任务使用结束后临时环境会消失，正式文件因已提交到仓库而保留。

## 在自己的仓库启用

1. 将公开版作为仓库根目录上传，或 Fork 已公开的仓库，并将 `main` 设为默认分支。当前本地同步读取 `main`，其他分支尚不支持。不要把私人工作区作为根目录整包上传。
2. 在 **Settings → Secrets and variables → Actions** 添加：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Secret | `LLM_API_KEY` | 自己的模型密钥 |
| Variable | `LLM_BASE_URL` | 兼容接口根地址，包含服务商要求的 `/v1` |
| Variable | `LLM_MODEL` | 模型实际名称 |
| Variable | `ENABLE_DAILY` | 填 `true` 后启用每日采编 |

3. 打开 **Actions → 每日情报采编 → Run workflow** 手动运行一次。Fork 后还需按 GitHub 提示启用工作流。
4. 查看执行摘要，确认日报和 `dist` 更新已保存。若仓库保护规则禁止工作流提交，请按自己的协作规则处理，不要关闭所有保护来绕过错误。
5. 本地设置填写这个公开仓库的 `owner/repository`，点击同步。

定时器默认 UTC 00:30，即北京时间 08:30。定时可能延迟或因 GitHub 状态而漏跑；手动运行会补当天未完成子任务，不会拿今天的榜单伪造过去的日报。长时间无活动的仓库可能被 GitHub 暂停定时，需要重新启用。

## 费用与模型

公开仓库的标准 GitHub 托管运行器依照 GitHub 当前政策免费，模型调用由所选服务商收费。工作流只使用标准 Linux 运行器。模型请求有输出上限、超时和重试上限，但这不是服务商账单硬限额；请在服务商控制台设置预算。

GitHub 托管任务中的 `localhost` 指云端电脑自身，不能直接访问个人电脑里的 Ollama。需要 Ollama 时使用本地 `serve --schedule` 或手动 `update`。

## 失败处理

模型、资讯源或榜单失败时分别记录，已有有效内容保留。部分成功的报告可先保存，工作流仍会显示未完全成功，便于及时发现问题。重新运行不会给同一项目重复计数。

工作流只提交白名单里的公开报告和构建产物。发现私人路径、疑似凭据或白名单外变化时停止提交，日志只显示脱敏原因。

官方说明：[Secrets](https://docs.github.com/en/actions/concepts/security/secrets)、[运行器与费用](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、[定时规则](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。
