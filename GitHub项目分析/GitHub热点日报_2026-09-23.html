#2
agent-substrate/substrate Go

Google 出品的 Agent 执行底座：一台机器上「塞」下百万级沙箱，闲置即休眠

⭐ 总计 3,197 今日 +245 ⑂ Fork 126
详细介绍

安全默认的 Agent 执行运行时，目标是以比标准容器高 10 倍的密度运行数百万沙箱：利用「Agent 大部分时间在闲着」的特性，把大量 actor（智能体实例）复用到少量常驻 worker 上，实测 8 个物理 Pod 承载约 250 个有状态 actor，超卖 30 倍以上。核心指标：suspend/resume 恢复操作低于 500ms、每秒超 500 次挂起/唤醒，唤醒时 RAM 与文件系统状态通过全量快照完整保留。基于 Kubernetes 做 Pod 级供给，内核层用 gVisor/microVM 做零信任隔离，框架无关——ADK、LangChain、Claude Code、MCP Server 都能跑。与 Firecracker 类方案的差异点在「为 Agent 而生」：不是 SDK，是规模化运行 Agent 的系统层。

适用领域

平台工程师与 Agent 基础设施团队：大规模托管编码/自主智能体时的沙箱调度层；云厂商与私有化部署场景降本（闲置即冻结）；K8s 运维背景想切入 AI Infra 的工程师

知识归类
E-基础设施/DevOps Agent基础设施 › 沙箱运行时

⭐ 总计 8,195 今日 +2,305 ⑂ Fork 342
详细介绍

Google 开源的声明式 Agent 编排运行时，今日 +2,305 stars 是榜单第一增速。口号是「声明一个 Agent 任务，AX 负责沙箱化、装工作区、锁网络、扩到集群规模」，官方直接类比：用过 Kubernetes 的话 ax 会很熟悉。四个原语覆盖 Agent 运维全链路：Task（沙箱内跑不可信代码，CPU/内存限额）、Workspace（预装 Git 仓库/MCP Server/技能包，Agent 冷启动即热）、Gateway（出站流量锁到显式白名单——Agent 乱花钱的主要防线）、Model（平台自身用哪个 LLM，凭据走 K8s Secret）。体验上 ax apply/watch/ssh/suspend/resume 全套 kubectl 风格命令，可随时 ssh 进沙箱「看 Agent 在干嘛」。跑在 Agent Substrate（榜单第 2 名）之上，两者构成 Google 的 Agentic Infrastructure 组合拳。

#7
superdesigndev/treg Python

「工具界的 OpenRouter」：一个 token 调 3000+ API，按次计费从一美分起

⭐ 总计 2,431 今日 +230 ⑂ Fork 228
详细介绍

treg 自述为「OpenRouter，但面向 Agent 工具而非模型」：一个 base URL + 一个 token，即可调用 60+ 供应商的 3000+ API 端点——SEO 与外链、社媒与趋势、企业/人脉信息 enrichment、广告、抓取、图像视频生成——按次计费低至一美分，无需逐家注册。核心设计是「按任务找工具而非按厂商」：treg catalog search "find a work email" 直接按用途检索。凭据阶梯设计很讲究：团队自持 key 的调用永不计量；无 key 时走 treg 的 key 按余额计费；代理层「只转发、不建模」上游请求，凭据服务端注入，调用方永远摸不到密钥。余额耗尽返回结构化 HTTP 402（含余额/预估费用/充值链接），Agent 无需解析自然语言即可自行处理。

适用领域

Agent 开发者免去逐家申请 API 的账号管理负担；营销/增长团队按需调用 SEO、社媒、enrichment 数据；小团队用「自己的 key 优先」策略零成本共享内部工具给全组的 Agent

知识归类
A-AI/机器学习 Agent基础设施 › 工具调用市场

#9
jev-chat/jev-chat-jarvis Kotlin

手机上的「聊天副驾」：微信里读懂对方意图，3 条候选回复一键填入，发不发你说了算

⭐ 总计 4,882 今日 ≈+1,200（近2日） ⑂ Fork 967
详细介绍

国产开源 Android App（macOS/Windows 版另有仓库），思路是「先判断、再写字」：先用判断模型给出对方真实意图、危险等级、该不该马上回，再据此起草回复，悬浮窗给出排好序的 3 条候选。技术路线上最讲究的是「不动聊天软件」：不 hook、不改包、不走平台接口、不读数据库，只用系统无障碍服务读屏幕上正在显示的对话——微信 8.0.52+ 混淆节点经伪装后 8.0.78 实测可读；飞书自绘正文不在无障碍树里，就用 ML Kit 离线 OCR 兜底。隐私设计：密钥存 App 私有空间，聊天内容只在分析瞬间发往用户自配接口，不落盘不进日志；发送权永远在用户手里，不碰转账红包。判断/回复/视觉三路接口分别可配，自带本地知识库与联系人档案。

适用领域

重度聊天用户（销售、商务、社恐人士）要聊天建议但不想交出账号；隐私敏感用户（key 自持、内容不落盘）；Android 开发者研究无障碍服务 + OCR 的合规采集范式

知识归类
